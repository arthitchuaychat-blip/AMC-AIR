**DB โหลดเต็ม 98% → แอปรวน/ช้า/ล็อกอินค้าง (2026-08-02, v568).** เจ้าของส่งจอ Supabase Infrastructure: **CPU/Compute 98%** + คำเตือน "exhausting resources". ต้นตอ "รวน/ค้าง/สิทธิดีด/ล็อกอินค้าง" ทั้งวัน = **DB แน่น** (ไม่ใช่บั๊กแอปตรง ๆ · แต่แอปกินแรงเกิน). ผมทดสอบ curl จากเครื่องเจ้าของ: default timeout 3/5 ครั้ง (IPv6 เสีย) · **บังคับ `-4` IPv4 เร็ว 0.3-1.8วิ ทุกครั้ง** → เน็ต office IPv6 มีปัญหาด้วย. จุดกินแรง: (1) **poll 3 ตัว × ทุก 20วิ × ทุกคน** (unreadByModule/countUnreadChats/countUnreadTeamChats) + realtime 3 channel/คน (2) **`_fetchAll` 128 จุด** = โหลดทั้งตาราง (3) countUnreadTeamChats→listChatRooms ทุก 20วิ. **แก้ (v568 · ฟรี):** poll 20000→60000 (App.jsx · realtime ยังสด poll=backup) · **mig 194** index เร่ง query ที่ยิงบ่อย (notifications(user_id) where read_at null = ตัวร้อนสุด + line/fb_contacts/messages/chat_messages/job_orders/job_visits/quotations/quotation_items). **ยังเหลือ (เฟสถัดไป เสี่ยงต้องทำระวัง):** รื้อ `_fetchAll` ที่โหลดทั้งตาราง → limit/กรองวันที่/เพจ (ทำทีละตาราง). **จ่ายเงิน (ทางเลือก):** อัปเกรด Supabase compute (Pro plan · Settings→Add-ons หรือ Infrastructure→Compute size) แก้ทันที แต่ถ้าไม่ optimize ด้วยจะตันอีก. **สรุปเจ้าของถาม "ต้องซื้ออะไรเพิ่มไหม" = ไม่ต้อง** (Supabase Pro พอ) แค่ optimize + ปรับ compute. ปิด IPv6 ที่ router ถ้าเน็ตยังติด ๆ ดับ ๆ.

**ต้นตอ CPU 98% จริง = แชต LINE ยิง query ถล่ม (2026-08-02, v569, mig 195).** วินิจฉัยด้วย `pg_stat_statements` (order by total_exec_time) — เจ้าของรันแล้วส่งผล: (1) `SELECT line_contacts.*` (โหลดทั้งตาราง+join line_contact_customers) เรียก **13k/30k/52k ครั้ง** รวม ~11ล้าน ms — จาก Chat realtime `loadContacts()` ที่ reload ทั้งตาราง**ทุกข้อความเข้า** × ทุกคนเปิดแชต × LINE OA คุยทั้งวัน (2) `chat_messages` **2.1 ล้านครั้ง** = N+1 ใน `listChatRooms()` (วน 2 query/ห้อง: last message + unread count) ที่ `countUnreadTeamChats()` เรียก + poll (3) `line_messages` avg 4.7วิ/ครั้ง (ค้นหา ilike — เรียกน้อย ผลต่ำ). **แก้ (v569):** (a) mig 195 `team_unread_count()` RPC นับ unread ทุกห้องใน query เดียว (join chat_members.last_read_at × chat_messages) → countUnreadTeamChats ใช้ rpc (fallback listChatRooms) (b) Chat.jsx realtime หน่วง loadContacts **3วิ** (เดิมยิงทุกข้อความ · ข้อความในห้องที่เปิดยัง append ทันที) (c) App nav badge 3 realtime หน่วง **4วิ**. **บทเรียน:** realtime `.on()` ห้ามสั่ง "โหลดทั้งตาราง" ตรง ๆ — ต้อง debounce · หลีกเลี่ยง N+1 ใน badge/poll → ใช้ RPC count ครั้งเดียว. ก่อนโทษ "เครื่องเล็กไป/ต้องจ่ายเพิ่ม" → ดู pg_stat_statements หา query ตัวจริงก่อนเสมอ (เจ้าของเกือบจ่าย XL $210/mo ทั้งที่ปัญหาคือโค้ดยิงถี่). ดู [[customer-chat]] [[supabase-1000-row-cap]].
