Document lifecycle features (v88–v90, 2026-06-19). Chain: **BOQ → ใบเสนอราคา → ใบแจ้งหนี้ → (ใบวางบิล) → ใบเสร็จ**, ใบงาน under quote. See [[cash-flow]] / [[permissions-system]].

**Cancel-in-order + delete (v88, migration `049_doc_cancel.sql` adds 'cancelled' to quotations + receipts status checks; boqs.status has no check so it's already allowed).** Every doc has a soft **"ยกเลิก"** (status=cancelled, keeps history) + the existing downstream lock (must cancel/delete the downstream doc first; cancelled downstream no longer blocks). Hard **"ลบ"** is gated to `role === "admin"` (ธุรการ) on all docs via `const canDelete = role === "admin"`. Cancel helpers: setBoqStatus/setQuotationStatus/setInvoiceStatus/setReceiptStatus/setJobStatus. Downstream flags (hasQuote/hasJob/hasInvoice/hasReceipt) and listDocLinks were updated to ignore cancelled rows, and Profit skips cancelled quotations (cash-flow seeding already skips cancelled invoices/receipts).

**Billing notes — ใบวางบิล (v89, migration `050_billing_notes.sql`).** `billing_notes` table (billing_no, customer_id, site_id, issue_date, note, invoice_nos text[], status open/cancelled). Module `billing` (admin/exec/finance/sales). `BillingNotes.jsx` (nav `billing`, between receipt & profit): create = pick customer → tick their UNPAID invoices → save; prints via DocSlip letterhead; each invoice row has "ออกใบเสร็จ" → routes to the existing per-invoice receipt flow (App onCreateReceipt → setReceiptFromInvoice). Receipts stay per-invoice (billing note is just a cover). Cancel soft + admin delete. api: listBillingNotes/saveBillingNote/setBillingNoteStatus/deleteBillingNote.

**Owner's lifecycle rules (v390, 2026-07-13) — MUST preserve in future doc work:**
1. ยกเลิก/ลบ ต้องไล่จากเอกสารล่าสุดย้อนไปเก่าสุดเสมอ — enforced: quote blocked by live POs (cancelLockMsg + docLinks.poNos), invoice blocked by live billing note (listInvoices returns `billingNo`), billing note blocked by member invoices with live receipts, BOQ blocked by live quote.
2. ยกเลิก/ลบ ต้องระบุเหตุผลเสมอ — `confirmDialog prompt.required:true` (ConfirmDialog.jsx disables ยืนยัน until reason typed); all doc cancel/delete call sites use it; setBoqStatus/setJobStatus/deletePurchaseOrder/cancelPurchaseOrder now logAudit with reason.
3. เอกสารที่ยกเลิกแล้ว ล็อกทุกปุ่มสร้าง/ทำงานต่อ (สร้างซ้ำ/แก้ไข/สร้างเอกสารลูก) — เหลือ ดู/พิมพ์/แชต/ลบ. **ข้อยกเว้น: BOQ ยกเลิกแล้วแก้ไขได้ — บันทึกสำเร็จ = revive (`_wasCancelled` → setBoqStatus(no, null))**.
4. เอกสารขายทุกใบต้องเริ่มจาก BOQ — new quotations require boq_no at save (legacy edits exempt); duplicate keeps source boq_no; BOQ picker excludes cancelled BOQs.
PO now has ยกเลิก button (open + unpaid only) via `cancelPurchaseOrder`.

**Sales-doc hardening sweep (v427, 2026-07-17 — no migration; all client/api layer).** From the 2-agent review (lifecycle + money):
- **Card-payment printing fixed**: invoice/receipt print rows now use `price_show ?? unit_price` (was raw unit_price → lines showed cash prices while totals were card-adjusted; quote printed correctly all along).
- **FlowAccount tax-invoice fixed**: full-receipt items use price_show and line discounts are folded into discountAmount (was dropping line discounts → FA totals inflated).
- **WHT base unified**: `snapshotItems` in Invoices/Receipts now computes amount = qty×price_show − line discount (same base as the quote); Receipts' snapshot also only flags wht for `customerType === "company"` (legacy-invoice fallback used to withhold from individuals).
- **Doc-number collisions**: BOQ/QT/BN genNo now second-precision (INV/REC already were) + `docNoTaken(table, no)` in api.js checked before every new-doc save — BOQ/QT/BN auto-regen a fresh number on clash, INV/REC ask the user (numbers are hand-editable). Saves are upserts that silently overwrite on collision — never remove this check.
- **_fetchAll everywhere**: all sales-doc header tables + lookups (listBoqs/listQuotations/listInvoices/listReceipts/listBillingNotes/listDocLinks) wrapped via `_allRows` helper — chain locks (hasQuote/hasReceipt/billedByQuote) were computed from capped-at-1000 reads.
- **Server-side chain guards now match the owner rules** (cancelled docs never block; UI-only locks got server twins): setInvoiceStatus/deleteInvoice ignore cancelled receipts + block cancel while in a live billing note; deleteBoq/deleteQuotation ignore cancelled children; setBillingNoteStatus/deleteBillingNote check live receipts fresh (`_bnLiveReceipts`); saveReceipt blocks cancelled/receipted invoices (duplicate receipts from 2 machines) and never revives a cancelled invoice (all invoice-status updates carry `.neq("status","cancelled")`); saveInvoice recomputes the quote grand fresh (`_quoteGrand`, same formula as listQuotations) and rejects over-100% billing + non-approved quotes.
- **Approved-quote lock**: editing an approved quotation is blocked; the ONLY path is the new "คืนสถานะแก้ไข" button (visible only when no live children) → setQuotationStatus("sent", reason) which logs `unapprove` to audit; editor's status dropdown no longer offers "approved" (approval only via the card button → audit).
- **Line discounts clamped** to the line amount (editor onChange + at save) — no more negative lines feeding WHT/subtotals.
- Billing notes: totals/wht/vat + printed rows + "ครบ" status now use live (non-cancelled) member invoices only (`liveInvoices` from api, `liveInv()` in component); listDocLinks excludes cancelled receipts from chips; invoice `vat_amt = round2(total − base)` kills the 1-satang drift; printDoc waits for `document.fonts.ready` (≤800ms) before measuring pagination.

**ส่งใบกำกับเข้า FlowAccount: VAT-only + กันส่งซ้ำ (v505, 2026-07-25 · mig 175).** เจ้าของสั่ง: ส่งเข้า FA ได้เฉพาะรายการ VAT + ส่งแล้วส่งซ้ำไม่ได้. ของเดิมหลวมทั้งคู่: ปุ่มยังกดส่งซ้ำได้ (แค่เตือน) · RPC `set_receipt_flowaccount` เขียนทับเลขเดิม · `catch(_){}` กลืน error ตอนประทับเลข → FA สร้างแล้วแต่เลขว่าง กดใหม่=ซ้ำ · เซิร์ฟเวอร์ไม่เช็ก VAT. **แก้ทั้งเส้น:** (1) VAT gate = `x.vat_amt > 0` (ยอด VAT บนใบจริง ไม่ใช่ธงใบเสนอที่อาจโหลดไม่ครบ) ทั้งปุ่ม+`sendToFlow`, เซิร์ฟเวอร์ `flowaccount-doc.js` ปฏิเสธ tax-invoice ที่ **vatAmount ที่คำนวณได้ = 0** (ไม่พึ่งธง isVat ที่ client ส่ง true เสมอ = dead code). (2) กันซ้ำแบบ **claim-before-send** (mig 175): `claim_receipt_flowaccount` UPDATE atomic `where flowaccount_id is null and flowaccount_at is null` → ยิงต่อเฉพาะจองได้ · `set_receipt_flowaccount` เขียนครั้งเดียว (`where flowaccount_id is null`) · `release_receipt_flowaccount` ปล่อยจองตอนส่งล้ม. **บทเรียนจากรีวิว (ผมออกแบบผิดรอบแรก):** อย่าใส่ auto-reopen ตามเวลา (เดิม claim ปลดล็อกเองถ้าค้างเกิน 10 นาที) — "ยังไม่เคยยิง" กับ "FA สร้างแล้วแต่ประทับเลขพลาด" มีสถานะ DB เหมือนกันเป๊ะ (id null + at ตั้งไว้) แยกด้วยเวลาไม่ได้ → 10 นาทีผ่านไปจองได้อีก=ส่งซ้ำ. แก้เป็น **ค้างจอง = บล็อกจนคนจัดการเอง**: ใบค้างส่ง (at set, no null) ปุ่มเปลี่ยนเป็น "⚠️ ค้างส่ง — จัดการ" → `resolvePending` เปิด dialog ให้เช็ก FA แล้วเลือก: กรอกเลข→บันทึก (ถือว่าส่งแล้ว) / เว้นว่าง→ปลดล็อกส่งใหม่. และ **claim ห้าม degrade เป็น SELECT ไม่ atomic** ตอน RPC หาย (schema-cache reload) — throw ให้ลองใหม่ ดีกว่าสองแท็บอ่าน null พร้อมกันแล้วจองทั้งคู่. กันถอยหลัง `app/test-flowaccount-send-once.mjs` (21 ข้อ · mutation verify). **ค้าง: เศษ 1 สตางค์บนใบกำกับงวดย่อย** — เซิร์ฟเวอร์คำนวณ VAT=base×7% แทน total−base ที่เก็บใน DB (ของเดิม ไม่ได้แก้รอบนี้). ดู [[stale-cache-deploys]]
