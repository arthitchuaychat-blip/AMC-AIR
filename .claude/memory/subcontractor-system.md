Subcontractor module (built 2026-06-16, v67). Teams can be `type` `permanent` or `sub` (set in ตั้งค่า → ทีมช่าง: sub teams also get phone/tax_id/bank_info/payout_rate). Sub teams are NOT employees → not in HR attendance/leave; managed as contractors paid per job.

Page **Subcontractor.jsx** (`subcontract` permission module; admin/exec/finance), 3 tabs:
- **ค่าแรง/งาน**: for each job assigned to a sub team, accounting fills labor per quote line item; each line defaults to `payout_rate`% (default 80%) of that line's sale, editable. Saved to `job_orders.labor_lines`/`labor_total`. Also a 1–5 rating + เคลม flag (`rating`/`is_claim`). **v231:** the editor built rows only from `quote.items`, so a job with no linked quotation (e.g. a cleaning job done alongside another team) opened empty and couldn't be filled → added "＋ เพิ่มบรรทัดค่าแรง" manual lines (editable name + ฿, delete ×, `manual:true` in labor_lines jsonb); restored on reopen via `saved.slice(fresh.length)`, kept by the reset button, which is hidden when there are no quote items.
- **จ่ายเงิน**: select completed+labored unpaid jobs per team → create `sub_payouts` batch. **หัก ณ ที่จ่าย 3% applies only to VAT-billed jobs' labor** (vatBase = sum labor of jobs whose quote.vat; wht = vatBase×3%; net = gross−wht). Creating marks the jobs `labor_paid` + `payout_id`. Then "บันทึกจ่ายเงิน" → **`PaySubModal` picks the paying bank account (v247, migration `091_subpayout_account.sql`)**.
  - **Bank-account link (v247):** `paySubPayout(id, {accountId, method, payDate})` (back-compat: still accepts a string method) stores `sub_payouts.paid_from` and inserts an `account_entries` **out** line (kind='payout', ref_type/ref_id=payout) into the chosen account → shows in เบิกจ่าย → เดินบัญชี & กระทบแบงค์ ([[expenses-system]]). Cash flow still comes from the `syncCashEntriesFromDocs` payout source (no double-count — separate tables). `deleteSubPayout`/`cancelSubPayout` delete that account_entries line; `updateSubPayout` updates its amount to the new net. paid_from update is PGRST204-resilient (retries without the column if mig 091 unrun).
- **สกอร์การ์ดทีม**: per team — งานเสร็จ/มูลค่า/ค่าแรง/จ่ายแล้ว/ค้าง/เคลม/เลื่อนนัด/คะแนนเฉลี่ย/กำไรเฉลี่ยต่องาน.

`Profit.jsx` now subtracts sub labor: net = sale − materialNet − labor (labor = Σ job.labor_total per quote's jobs). Labor + WHT math is Node-verified.

Data: migration `042_subcontractor.sql` (teams: type/phone/tax_id/bank_info/payout_rate; job_orders: labor_lines/labor_total/labor_paid/payout_id/rating/is_claim; new `sub_payouts` table, RLS admin/exec/finance). The user must run it. Future ideas they mentioned: split labor when permanent+sub on one job; subcontractor payment voucher / WHT certificate doc.
