- **Bank reconciliation (v241, 2026-07-02, migration `089_account_reconcile.sql`):** `account_entries` gained `reconciled bool` + `reconciled_at`. The ledger tab (`ReportTab`→"เดินบัญชี & กระทบแบงค์") now: account chips (defaults to first bank account), a "＋ เพิ่มรายการ (ฝาก/ถอน)" button opening `AddEntryModal` (manual in/out entry, kind='manual'), summary cards (ยอดตามระบบ / ✓กระทบแล้ว = opening+Σreconciled signed / ⧗ยังไม่กระทบ / statement input → ผลต่าง target ฿0), a "แสดงเฉพาะที่ยังไม่กระทบ" toggle, "✓ กระทบทั้งหมดที่แสดง" bulk button, and a per-row reconcile checkbox. Manual entries (kind='manual') are deletable; auto ones (expense/transfer/receipt) locked. **Why manual entries exist:** account_entries only got money OUT (payExpense) + transfers before — no way to record deposits/customer-payments IN, so bank balance never matched statements. `recErr()` maps PGRST204/column errors to "รัน migration 089 ก่อน".
- **Monthly view + opening carry-forward (v244, 2026-07-03):** the ledger tab now has month nav (◀ thMonth ▶ · "เดือนนี้" · "ทุกเดือน" toggle; state `anchor`/`allMonths`) shown only for a single account. Editable **ยอดยกมาตั้งต้น** = `accounts.opening_balance` via `setAccountOpening(accountId, amount)` (input, onBlur save). Running balance: **ยอดยกมาต้นเดือน** = opening_balance + Σsigned(entries before monthStart); **ยอดคงเหลือสิ้นเดือน** = ยอดยกมา + monthIn − monthOut → equals next month's opening automatically (no stored per-month anchor — pure derivation). Entries filtered to [monthStart,nextStart); reconcile checkboxes + statement diff scoped to the month (diff = statement − closing, target ฿0). "all accounts" chip = no month nav, shows every entry. Summary cards reuse `.exp-accounts`/`.exp-acc`.
- **Customer deposits from receipts → bank ledger (v242, 2026-07-03):** `syncBankReceipts()` pulls **paid** receipts (skips payment_method 'เงินสด' = not a bank deposit) into `account_entries` as `direction:'in', kind:'receipt', ref_type:'receipt', ref_id:receipt_no`. **Account routing:** payment_method ∈ {"Trade Account","Trade Baht"} → `trade` account (single, no VAT split — v243); else vat_amt>0 → `vat` account, else → `novat` account (matches the two "บัญชีธนาคาร VAT / ไม่ VAT" wallets). Receipts.jsx METHODS renamed "Trade Account"→"Trade Baht" (sync still matches both strings so old receipts route correctly). If `trade` account missing (mig 090 not run) Trade receipts fall back to VAT routing. Amount = `net` (after WHT — what actually lands in the bank), fallback `total`. Idempotent (insert new / update unreconciled / delete stale for cancelled/deleted), and NEVER touches `reconciled=true` lines. Existing-entries select is resilient to a missing `reconciled` column (pre-089). Fired fire-and-forget from `saveReceipt`/`setReceiptStatus`/`deleteReceipt` (alongside syncCashEntriesFromDocs), and auto-runs + has a "ดึงยอดรับเงินจากเอกสาร" button on the reconcile tab. Non-office users' background call just fails silently (account_entries RLS office-only) → caught on next office open. NOTE: receipt deposits go to the *account ledger* only, not `cash_entries` (Cash Flow already seeds receipts separately). KIND_TAG receipt = "💰 รับเงินลูกค้า".

**Finance hardening (v433, 2026-07-17 — needs migration `147_finance_hardening.sql`).** From the finance review:
- 1000-row caps closed: `listAccounts` (wallet balances!), `listAccountEntries` (was .limit(2000) — Supabase caps at 1000 anyway; oldest rows vanished first → opening-carry-forward/reconcile broken), `listPayables` (oldest unpaid POs vanished first), `listExpenses`/`listMyExpenses`.
- `decideExpense`: blocks reject when paid_amount>0 (partial-paid reject used to erase the real expense_paid cash line + resurrect the PO debt = double payment) + blocks self-approval except admin/exec (same pattern as HR lockSelfId).
- `payExpense`: only status approved payable + optimistic lock on paid_amount (`.eq/.is` previous value, `.select("id")` row check) — two clerks paying the same request simultaneously now conflict instead of double-paying.
- `createSubPayout`: server-side fresh remaining check + optimistic labor_paid_amt bump with rollback (deletes the payout on conflict). `paySubPayout`: paid_at = payDate at 12:00Z (cash-flow line lands on the user-chosen date, not click date; no more UTC previous-day before 7am).
- Reconciled (✓) ledger lines are now untouchable: updateAccountEntry/deleteAccountEntry guard, updateTransfer/deleteTransfer guard both legs, bookSalaryEntry/removeSalaryEntry delete only unreconciled (book skips insert if a reconciled row remains).
- `upsertPayrollCashEntry` now writes status **actual** (paid payroll finally counts in "เงินจริงสะสม" — matches the bank ledger).
- Advances → cash flow: sync seeds `advance` lines (hr_advances with paid_out_at; actual out) — ONLY when the syncing user is office (admin/exec/finance/hr): hr_advances RLS silently filters rows for other roles and the stale-delete would wipe other people's lines (mig 085 lesson). Pre-147 the insert falls back without advance rows. MANAGED includes 'advance' only when the read succeeded.
