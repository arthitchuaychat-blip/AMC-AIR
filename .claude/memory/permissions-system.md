Access control lives in `app/src/lib/permissions.js`. Each (role × module) has a level `none|view|edit`. `can(role, module, "view"|"edit")` and `navForRole(role)` drive everything. `DEFAULT_PERMS` is the shipped design (ธุรการ/admin is the most powerful; ธุรการ **and** ผู้บริหาร/exec are the system admins who can edit settings/users; ฝ่ายขาย/sales keeps profit visibility).

`App.jsx` builds the sidebar from `navForRole(role)` and loads admin overrides via `getRolePermissions()` → `setPerms(mergePerms(...))`. Every page's edit gate now calls `can(role, "<module>", "edit")` instead of a hardcoded role array. Exception: Movements purchase/damage/cancel stays restricted to office/stock roles (`role !== "tech" && role !== "lead_tech"`) even when field roles have movements edit (withdraw/return).

**JobOrders (ใบงาน) field-tech scoping (v218):** field roles (`tech`, `lead_tech`) see only jobs whose `assigned_team` matches their own `profiles.team` — a UI filter in JobOrders.jsx (`fieldOnly` → `baseList`), NOT RLS. The team-filter row is hidden for them and status counts use `baseList`. `tech.joborders` default raised N→V so regular ช่าง can open the menu; note the `me` prop here is the author *name string*, so the team comes via a separate `myTeam={profile?.team}` prop. The old per-tech "ช่างทุกคน" dropdown was removed (redundant with the team chips). Caveat: if an admin previously **saved** the permission matrix, the saved `tech.joborders` override may still be `none` — they'd re-enable it in ตั้งค่า.

Overrides are stored as one JSON row in `app_config` (key `role_permissions`), edited in **ตั้งค่า → สิทธิ์การใช้งานตามตำแหน่ง** (a role×module grid, admin/exec only). Requires migration `039_role_permissions.sql` (creates `app_config` with RLS: all read, admin/exec write) — the user runs migrations manually. Until it's run, `getRolePermissions()` errors and the app falls back to `DEFAULT_PERMS` (saving the matrix will fail with a hint to run 039).

**Roles (10, as of v213 / 2026-06-28):** admin(ธุรการ), exec(ผู้บริหาร), finance(บัญชี), hr(ฝ่ายบุคคล), sales(ฝ่ายขาย), graphic(กราฟิก), stock(ธุรการวัสดุ), lead_tech(หัวหน้าช่าง), tech(ช่าง), maid(แม่บ้าน). hr/graphic/maid added in v213. **Two-layer gotcha:** permissions.js only controls UI visibility — a role also needs **RLS** on the tables its modules touch. New roles required migration `082_new_roles.sql` (widen `profiles.role` check constraint via a DO-block that drops any role check first, then add hr to HR tables + profiles update, graphic to web_clients/banners/portfolio/articles/press/ads + web_orders read). teamchat/tasks/expenses(self)/profiles-read(`true`)/materials-read(`true`) are already open so maid needed no RLS change. Settings.jsx role-assignment dropdown now derives from `PERM_ROLES`/`PERM_ROLE_LABEL` (was a separate hardcoded list — keep it that way so new roles propagate). HR payroll→cashflow link is best-effort (`.catch()`) so hr-role (no cash_entries RLS) can still run payroll.

To add a new module/menu: add it to `MODULES` (also sets sidebar order + whether it has an edit level) and to every role in `DEFAULT_PERMS`. `mergePerms` keeps old saved overrides valid against new modules. Verify changes with the Node + browser-harness approach (see [[print-pagination]]).

**HR expanded to sales + payments + petty cash (v249, 2026-07-03):** `hr` DEFAULT_PERMS is now the **union of HR's own perms + all sales perms** (customers/quote/invoice/receipt/billing/boq/chat/website/weborders/followup/joborders/handover/schedule/catalog/subcontract all raised to sales' level; keeps hr:E, cashflow:E, expenses:E) — because HR also does sales work. Plus HR can **approve/pay เบิกจ่าย + control petty cash**: `OFFICE` in Expenses.jsx now includes "hr" (reveals อนุมัติ/จ่าย + บัญชี&โอนเงิน + เดินบัญชี tabs), and migration `093_hr_expense_petty.sql` widens RLS `er_read`/`er_update` (expense_requests) + `acc_rw` (accounts) + `ae_rw` (account_entries) to include 'hr'. cash_entries already had hr (085). submitExpense now notifies hr too. **Two-layer reminder in action:** giving HR the approve UI required BOTH the OFFICE array (UI gate) AND the RLS widen — perms.js alone wasn't enough since Expenses tabs are OFFICE-gated and the writes hit admin/exec/finance-only RLS. If an admin previously saved the permission matrix, the hr overrides may need re-toggling in ตั้งค่า.

**HR sales access — the full fix (v253, 2026-07-03):** after v249 the user reported "HR ใช้สิทธิฝ่ายขายไม่ได้". Two causes, both hit: (1) **saved app_config override masks the new defaults** — Settings saves the FULL merged matrix, so hr's old restricted values win over the code default forever until re-saved. Fix: added a **per-role "↺ รีเซ็ต" button** in `PermissionsCard` (Settings.jsx) → `resetRole(role)` sets just that column to `DEFAULT_PERMS[role]` (doesn't wipe other roles like the existing "คืนค่าเริ่มต้น" does), then บันทึก. (2) **RLS second layer** — sales-domain tables' write policies never included hr. Migration `095_hr_sales_access.sql` mirrors sales→hr on ~28 policies: customers/contacts/sites, boqs/boq_items, quotations/quotation_items, invoices, receipts, billing_notes, job_orders, job_visits, job_handovers, doc_term_presets, materials, brands, btus, quick_replies(read+write), line_contacts(read+update), line_messages(read), line_contact_customers(read+write), fb_contacts/fb_messages(write), web_orders(read+update). (line_messages has no client write policy — customer messages are sent server-side via edge function.) **General rule when "make role X like role Y": mirror Y→X in BOTH permissions.js AND every RLS policy containing Y, then reset X's saved-override column.**

**Roles relabel/reorder + ผู้ช่วยช่าง (v519, 2026-07-28, mig 182):** เจ้าของจัดชื่อ/ลำดับตำแหน่งใหม่ (ROLES order + ROLE_LABEL: exec ผู้บริหาร, admin ธุรการ, finance บัญชีการเงิน, hr บุคคล, sales ขาย, graphic การตลาดและกราฟิก, stock คลังสินค้าวัสดุ, maid แม่บ้าน, lead_tech หัวหน้าช่าง, tech ช่าง, assistant ผู้ช่วยช่าง) — ดรอปดาวน์ตำแหน่ง + ตารางสิทธิ์อ่านจาก ROLES/ROLE_LABEL ที่เดียว. **role ใหม่ `assistant` (ผู้ช่วยช่าง) = เหมือน tech ทุกอย่าง.** ทำ 2 ชั้น: (1) permissions.js DEFAULT_PERMS.assistant = สำเนา tech + เพิ่ม 'assistant' คู่ 'tech' ในเช็ค field-worker ทุกจุด (App.canBurmese, api saveProfile/createUser team-keep, Expenses/JobOrders/Schedule fieldOnly, Handover canEditRow, InternalNote FIELD_ROLES, Movements isAdmin/isTech, Settings team-enable ×2, TeamChat techRoles, Tools people). (2) **RLS ชั้นเดียวจบด้วยเทคนิคใหม่แทนการไล่แก้ทุก policy**: mig 182 แก้ `my_role()` ให้คืน 'tech' เมื่อ role='assistant' (`case when role='assistant' then 'tech' else role end`) → ทุก policy ที่ให้สิทธิ์ tech ครอบคลุม assistant ทันที; แอปยังอ่าน profiles.role='assistant' ตรง ๆ จึงแยกป้าย/เมนูได้. mig 182 ยังขยาย profiles_role_check เพิ่ม 'assistant'. assistant เป็น role ใหม่ ไม่มีใน saved override → mergePerms คืน DEFAULT_PERMS.assistant เอง ไม่ต้อง reset. my_role()/my_team() นิยามอยู่ใน schema ฐาน (ก่อน mig 008) ไม่อยู่ในโฟลเดอร์ migrations — rollback my_role อยู่ท้ายไฟล์ 182.
