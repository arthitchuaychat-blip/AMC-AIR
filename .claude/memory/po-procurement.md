Procurement redesign (v274, 2026-07-04 — needs migration `100_po_procurement.sql`: purchase_orders + quote_no text, expense_id uuid, paid_at timestamptz). Designed around the user's process: **AC is bought only per customer order; materials optionally per order.** See [[expenses-system]] / [[cash-flow]] / [[suppliers-system]].

- **PO ↔ quotation:** PO editor has "อ้างอิงใบเสนอราคา" Combo (`listApprovedQuotesLite()` — approved quotes only). RULE enforced in save(): a PO containing any `kind==='ac'` item MUST have quote_no; material-only POs optional. savePurchaseOrder head includes quote_no (surgical PGRST204 fallback list: price_incl/vat/quote_no — drops ONLY the column named in the error, see v271 lesson).
- **Job costing (user chose "รับของแล้วเบิกเข้างานให้เลย"):** receiving a quote-linked PO auto-records a **withdraw batch to the quote's job at the PO's actual (pre-VAT, per-base-unit) price** right after the purchase batch. Flow: App.jsx onReceive passes quoteNo → Movements prefill resolves receiveJob from jobOrders (quote_no match, non-cancelled) → submitCart, after WMA + markPoReceived, records withdraw txns from the same `norm` (base-unit qty + unitCost). Profit math unchanged (uses วัสดุเบิกจริง) → actual order cost lands on the job with NO double count. If no job order exists yet for the quote → auto-withdraw silently skipped (received to stock only).
- **Payment via เบิกจ่าย (approval + account + ledgers):** PO card "💳 ส่งขออนุมัติจ่าย" → `requestPoPayment(po)` inserts an expense_request (category "ซื้อสินค้า (PO)", amount = grand total incl VAT, **job_no ALWAYS null** — job cost already flows via withdrawals; job-linking would double-count in jobExpenseCost) and stamps purchase_orders.expense_id; notifies admin/finance/exec/hr. `payExpense` detects a PO linked by expense_id → stamps po.paid_at (+sync) and **skips the cash_entries 'expense' mirror** (the PO line becomes the actual — else double count); account_entries bank line still written (reconciliation). `decideExpense(rejected)` clears expense_id → PO back to unpaid, can resend.
- **2-axis PO status:** receive axis (รอรับของ/รับแล้ว/ยกเลิก, existing `status`) × payment axis derived `paymentStatus` = paid_at?paid : expense_id?pending : unpaid. Separate filter chip rows (PAY_FILTERS blue) + 💳 badge on cards.
- **Cash flow rule changed:** PO line = projected from creation (no approval step — user chose create=ordered), flips to **actual on paid_at** (payment date), NOT on receiving (credit terms supported both directions). syncCashEntriesFromDocs selects paid_at with pre-100 fallback (legacy: received≈paid).
- **PO print:** DocSlip with `partyLabel="ผู้ขาย"` (new DocSlip prop), company = vat?companies.vat:novat, supplier info matched by name from suppliers register, columns identical to sales docs, totals ก่อนVAT→VAT→รวม, signs ผู้สั่งซื้อ/ผู้อนุมัติ.
- **Pending-PO cost counts immediately (v277):** user paid POs but hadn't pressed รับสินค้า → job profit missed the cost. Now quote-linked POs with status **open** add their pre-VAT `subtotal` to the job's actual cost as "ค่าสินค้าตามใบสั่งซื้อ (ยังรอรับของ)" (poPendByQuote in both Profit.jsx + SalesReport). No double count: counted ONLY while open — receiving flips status to received AND auto-withdraws, moving the cost into เบิกจริง. Visible as 🛒 tag on Profit rows + a waterfall line.
- **Profit formula switched to ACTUAL cost (v276, user chose "ใช้ต้นทุนจริง"):** กำไรสุทธิ = ขาย − (เบิกจริง−คืน + ค่าแรงซัพ + เบิกจ่าย) in BOTH Profit.jsx and SalesReport กำไรต่องาน. BOQ is now "กำไรตามประมาณการ" (reference column/line only) — it is NO LONGER subtracted in net, fixing the double-count once PO-linked receiving auto-withdraws the same goods. Jobs with zero recorded actual cost show net "—" (ยังไม่บันทึกต้นทุนจริง) instead of a fake near-100% profit; KPI sums/margins computed only over jobs with actuals. Salesperson/team tables + KPI cards stay BOQ-based, relabelled "(ประมาณการ)". v275 added a loud warning when receiving a quote-linked PO whose quote has no job order yet (else auto-withdraw silently skips and cost stays in stock).
- **Gotcha:** editing PO amounts after ส่งขออนุมัติจ่าย leaves the expense amount stale — reject the request (unlinks) and resend. Cancel-receipt (v273 cancelTransactionGroup) reopens the PO but does NOT reverse the auto-withdraw batch — cancel that withdraw group separately if needed.
