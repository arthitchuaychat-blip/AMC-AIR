**Architecture:** LINE Messaging API → Vercel **Node.js** serverless functions → Supabase REST → Chat page (Supabase Realtime). (Started on edge runtime but edge could NOT reach api.line.me — caused 504 hangs + no profile names + broken replies — so both functions were moved to Node runtime. Functions call Supabase via raw REST/fetch, NOT supabase-js, because supabase-js failed on edge.)
- `app/api/line-webhook.js` (Node, `config.api.bodyParser=false`, reads raw body for HMAC-SHA256 signature via node:crypto) — upserts `line_contacts` (fetches LINE profile, refreshes name on later msgs if still "LINE User"), inserts `line_messages`, saves image messages to Storage `photos/line/`, bumps unread via `line_bump_unread` RPC. Debug probes (GET): `?check=1` (env presence), `?dbcheck=1` (table read), `?selftest=1` (DB write steps), `?linetest=1` (api.line.me reachability). Test a signed webhook with: `printf '%s' '<json>' >f; openssl dgst -sha256 -hmac "$CHANNEL_SECRET" -binary <f | base64` as `X-Line-Signature`, POST `--data-binary @f`.
- `app/api/line-send.js` (Node) — push reply; authorizes caller by Supabase JWT (`/auth/v1/user`) + office role, then inserts the `out` row.
- Test contact rows to clean up in SQL: `delete from line_contacts where line_user_id in ('Urealtest12345','Uselftest_delete_me','Unodetest777');` (messages cascade).
- DB: migration `supabase/migrations/023_line_chat.sql` (tables `line_contacts`, `line_messages`, RPC, RLS for office roles, adds both tables to `supabase_realtime` publication).
- App: `app/src/components/Chat.jsx`, api helpers in `app/src/lib/api.js` (listLineContacts/listLineMessages/sendLineMessage/linkLineContact/markLineRead). Nav key `chat`.
- `app/vercel.json` rewrite excludes `/api` so the SPA catch-all doesn't swallow function routes.

**Vercel env vars required (user sets in Vercel → Settings → Environment Variables):** `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`. Never ask the user to paste these into chat — they set them in the dashboard.

**Activation steps (user-side, one-time):** enable Messaging API on the LINE OA at developers.line.biz → copy Channel secret + access token → set the 4 Vercel env vars → set webhook URL `https://<app-domain>/api/line-webhook` in the LINE console + turn on Use webhook → run migration 023 in Supabase. Reply only from the app (messages typed in LINE OA Manager don't reach the in-app board).

**Multi-customer per LINE chat (added 2026-06-28, v212, migration 081):** one LINE thread can link several customers (a person who is both a personal + a company customer). `line_contacts.customer_id` stays the **active** customer (drives the info panel/docs/confirm — all single-customer logic unchanged); the new `line_contact_customers` join table holds all linked customers. `listLineContacts` attaches `custIds[]` per contact (resilient if the table isn't created). api: `addLineCustomer(uid,cid)` (link + make active) / `removeLineCustomer(uid,cid)` (unlink, fall back). Chat info panel renders customer chips: click to switch active, × to unlink, "+ เพิ่มลูกค้า" Combo to add. FB stays single-customer.

**Auto-reply (added 2026-06-25, v183, migration 073 — rule-based, NO AI):** `line-webhook.js` auto-replies to inbound 1-on-1 messages via the event's `replyToken` (free, no push quota). Two triggers: (1) welcome on a contact's first-ever message (`ensureContact` now returns isNew), (2) after-hours message when outside business hours, with a per-contact cooldown (`line_contacts.last_autoreply_at`, default 120 min) so it doesn't reply to every off-hours message. Business hours computed in Thai time (UTC+7). Config lives in `app_config` key `autoreply` (enabled/welcome_text/afterhours_text/open_days/open_time/close_time/cooldown_min), edited via the "ตอบแชต LINE อัตโนมัติ" card in Settings (`getAutoReply`/`saveAutoReply`). The auto-reply is stored as an outbound `line_messages` row so staff see it. User chose this over AI-assist/AI-auto (AI not built — would need an Anthropic key + cost).
