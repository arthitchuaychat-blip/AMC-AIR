HR system (built 2026-06-16, v63). Two pages + permission modules `attendance` (everyone, self-service) and `hr` (admin/exec).

- **Attendance.jsx** (เข้างาน/ลา): selfie (`<input capture=user>`) + GPS check-in/out → `hr_attendance`; auto late/OT from `lib/hr.js dayStat()`. Leave requests (sick/personal/vacation) sized by working days `leaveDays()`; remaining balance = quota − approved this year. **Gotcha (v221):** the check-in button is `fileRef.click()` on a `capture="user"` file input — **LINE/Facebook in-app browsers and bare Android WebViews block the camera**, so the button "does nothing" (no error). `inAppBrowser()` (UA sniff: `Line/`, `FBAN|FBAV|FB_IAB`, Instagram/Messenger/WeChat/TikTok, `; wv)`) shows an orange warning + copy-link telling them to open in Chrome/Safari or add-to-home-screen. So "X can't check in" but others can = X opened the app inside an in-app browser, not a code/account bug.
- **HR.jsx** (admin): today dashboard (in/late/absent/leave), leave approval (`decideLeave`), monthly report (worst-first ranking + CSV export), per-staff กะ (work_pattern + sat_group), holidays, settings (work hours/grace/quota).
- **lib/hr.js** (pure, Node-tested): `isWorkday(date,pattern,satGroup,holidaySet)`, `dayStat`, `leaveDays`. Patterns: `mon_sat` / `mon_fri` / `mon_fri_alt_sat` (เสาร์เว้นเสาร์ via week-parity: A=even weeks, B=odd) / `none`. Default hours 08:00–17:00, grace 15m, quota พักร้อน6/ลากิจ3/ลาป่วย30 (Thai law defaults, editable).

Data: migration `041_hr.sql` (hr_attendance, hr_leaves, hr_holidays, hr_leave_quota + profiles add hire_date/department/work_pattern/sat_group; RLS self + admin/exec). hr_settings stored in `app_config` (needs migration 039 from [[permissions-system]]). Selfies → existing `photos` storage bucket (`uploadAttendancePhoto`).

**Payroll + Performance (v98–v99, 2026-06-20 — needs migration `051_payroll.sql`).** Pay cycle: **cut-off 25th** (period = 26th prev → 25th this month via `payPeriod(ym)` in `lib/payroll.js`), paid month-end. Per-employee pay settings on `profiles` (mig 051): `pay_type` monthly|daily, `base_pay`, `ot_rate` (฿/OT-hr), `sso` bool — edited in HR → กะ&ตั้งค่า ("ค่าจ้าง/เงินเดือน" card). HR tab **"เงินเดือน"** (`PayrollTab`): `periodStats()` + `computePayslip()` (pure, lib/payroll.js) → base (monthly=full / daily=present×wage) + OT(hrs×rate) − late(lateMin→hr×hourly) − absence(monthly only) − over-quota-leave(annual used−quota, monthly) − SSO 5% cap 750; editable bonus/other-deduct; saves to `payslips` table (one per period+user, status draft|paid), "บันทึกรอบ"/"ทำจ่ายทั้งรอบ". api: listPayslips/savePayslip/setPayslipPaid. HR tab **"ประสิทธิผล"** (`PerfTab`): per-employee scorecard = attendance (on-time%/absent/late/OT from periodStats) + their **team's** jobs (done/avg rating/claims/reschedule — jobs link to team, not person) → composite score (on-time 50% + present 20% + rating 30% − claims×5). Both gated to admin/exec via HR module; payslips RLS admin/exec/finance.

**Cash advances / เบิกเงินล่วงหน้า (v125, 2026-06-21 — needs migration `053_advances.sql`).** Staff request from **Attendance.jsx** ("เบิกเงินล่วงหน้า" card: amount+reason → `submitAdvance`); see own list + cancel while pending (`listMyAdvances`/`cancelMyAdvance`). HR tab **"เบิกล่วงหน้า"** (`AdvancesTab`) approve/reject (`listAdvances`/`decideAdvance`). Status flow pending→approved→paid (+rejected). Approved-and-unsettled (period null) advances are auto-summed per user in `PayrollTab` and deducted as `dAdvance` (computePayslip in lib/payroll.js; payslips.d_advance col; new "หักเบิกล่วงหน้า" table column + slip line); on "ทำจ่ายทั้งรอบ" they're settled via `markAdvancesPaid(ym, ids)` (status=paid, period=ym) so they never double-deduct. Table `hr_advances` RLS = self OR admin/exec/finance. NOT wired into cash flow ledger.

**Setup the user must do:** run migration 041 (and 039 if not yet) + `053_advances.sql` in Supabase, then in บุคคล(HR) → กะ&ตั้งค่า set each staff's work_pattern (sales 2 คน = mon_fri_alt_sat, groups A/B).

**Unpaid + hourly leave (v407, 2026-07-16 — needs migration `141_leave_unpaid_hourly.sql`).** Leave type `unpaid` (ลาไม่รับค่าแรง): no quota (balance cards skip it), ALWAYS deducted for monthly staff via the over-quota channel — in PayrollTab `st.overLeave = min(leaveDays − unpaidLeave, over) + unpaidLeave` (daily-wage staff naturally unpaid via absence math). Hourly leave (ลาราย ชม.): rows carry `hours/time_from/time_to`, days stored as fraction (`LEAVE_HOURS_PER_DAY = 8`, half-hour steps); `buildLeaveDaySet(leaves, from, to)` in lib/hr.js returns `{t, h}` per user-day and is the SINGLE builder used by today/report/perf/payroll — an hourly-leave day still counts attendance (present/late/absent) and shows a blue "ลา x ชม." tag; `leaveFrac`/`leaveAmountText` helpers. submitLeave/updateLeave pass hours through with pre-141 fallback (strip columns on error).

**HR hardening batch (v423, 2026-07-17 — needs migration `144_ot_approval.sql`).** From the HR review:

- **OT approval mode** (`settings.otNeedsApproval`, toggle in กะ&ตั้งค่า — the flag existed since day 1 but nothing used it): when ON, OT counts toward payroll/report **only** on days HR pressed "รับรอง OT" (TodayTab button → `setAttendanceOtOk` → `hr_attendance.ot_ok`, mig 144). Gating lives in `periodStats` (payroll.js) + ReportTab's inline loop; tags show "· รอรับรอง"/"✓". OFF (default) = old behavior, safe to deploy before running the migration.
- **TodayTab shows the evidence**: check-in/out selfie thumbnails (click = full) + 📍 GPS link per row (columns existed since 041, never displayed).
- **Forgot-checkout banner**: TodayTab amber banner lists last-7-days rows with check_in but no check_out; click opens AttEditModal for THAT day (edit state now `{p, a, day}` — modal uses `edit.day || day`).
- QuotaCard inputs save onBlur (was an API call per keystroke).

**Position = role, single source of truth (v215, 2026-06-28).** HR job position ("ตำแหน่งงาน") is no longer a separate free-text `profiles.department` + editable positions list — it's now **derived from the person's `role`** via `ROLE_LABEL` (from [[permissions-system]]) at the data layer. `posLabel(p) = ROLE_LABEL[p.role] || p.department` lives in api.js and is applied in `listHrStaff` / `listAttendance` / `listLeaves` / `listAdvances`, so every HR tab shows the same position as ตั้งค่า. The StaffTab editor (add/remove positions + per-staff department input + `getPositions`/`savePositions`/`DEFAULT_POSITIONS` + `hr-positions` datalist) is gone, replaced by a **read-only** reference card listing the role-based positions held by **permanent staff** (counts per position). To change someone's position, assign their role in ตั้งค่า → ผู้ใช้งาน. `listHrStaff` already returns permanent staff only (excludes `teams.type='sub'` members). Also fixed a latent bug: `setPattern` was `(p, fields)` but the work_pattern/sat_group `<select>`s call it `(p, key, val)` — it now accepts both, so those dropdowns actually save.
