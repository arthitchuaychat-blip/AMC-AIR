# AMC Stock → ระบบหลักบริษัท (Roadmap v2)

ต่อยอดระบบวัสดุ → ขาย/เสนอราคา/สั่งงาน ครบวงจร สำหรับธุรกิจติดตั้ง-บริการแอร์

## วงจรเป้าหมาย
```
ลูกค้า(CRM) → BOQ(ต้นทุน) → ใบเสนอราคา(ราคาขาย) → อนุมัติ → ใบงาน → มอบทีมช่าง+นัดวัน → ช่างทำงาน(เบิกวัสดุ) → ต้นทุนจริง
                                        └──── กำไร = ยอดขายสุทธิ(ใบเสนอราคา) − ต้นทุนสุทธิ(BOQ) ────┘  [เฉพาะใบที่อนุมัติ]
```

## 1) คลังสินค้า/บริการ (Catalog v2) — 3 หมวดใหญ่ + ตัวกรอง
ขยาย "วัสดุ" เดิม → ตาราง `items` ที่มี **type**:
- **ac (เครื่องปรับอากาศ):** + ยี่ห้อ (brand) + ขนาด BTU → กรองตามยี่ห้อ/BTU ได้
- **service (บริการ):** ค่าบริการต่าง ๆ (ไม่มีสต๊อก)
- **material (วัสดุ):** หมวดย่อยเดิม (ท่อทองแดง/น้ำยา/สายไฟ ฯลฯ) — นับสต๊อก
ทุกชิ้นมี: รหัส · ชื่อ · ต้นทุน · ราคาขาย · รายละเอียด · รูป · (วัสดุ/แอร์ที่เก็บสต๊อก: ขั้นต่ำ+คงเหลือ)
หน้าคลัง: ตัวกรองตาม type + ยี่ห้อ/BTU (แอร์) + หมวดย่อย (วัสดุ) + ค้นหา

## 2) CRM — ลูกค้า
- `customers`: ประเภท (นิติบุคคล/บุคคลธรรมดา) · ชื่อ · ที่อยู่หลัก · เลขผู้เสียภาษี · **คิด VAT? (เลือกได้)** · หมายเหตุ
- `customer_contacts`: ผู้ติดต่อหลายคน (ชื่อ · เบอร์ · ตำแหน่ง) — เลือกได้
- `customer_sites`: ที่อยู่ให้บริการหลายไซต์ (ชื่อไซต์ · ที่อยู่ · ลิงก์แผนที่)
- หน้า: รายชื่อลูกค้า · เพิ่ม/แก้ · รายละเอียด (ผู้ติดต่อ/ไซต์/ใบเสนอราคา/งาน)

## 3) BOQ (ใบประมาณการต้นทุน — ภายใน, แสดง "ต้นทุน")
4 ส่วน แต่ละส่วนใส่ได้หลายรายการ:
- **6-1 เครื่องปรับอากาศ** (สินค้า AC)
- **6-2 วัสดุแถมลูกค้า** (ไม่คิดเงิน — แต่เป็น "ต้นทุน" ของเรา)
- **6-3 วัสดุคิดเงินเพิ่ม**
- **6-4 ค่าบริการ**
รวม "ต้นทุนสุทธิ BOQ" = ทุกส่วน (รวม 6-2 ด้วย เพราะเป็นต้นทุนจริง)

## 4) ใบเสนอราคา (Quotation — ราคาขายให้ลูกค้า)
- อ้างอิง BOQ หรือไม่ก็ได้ · ถ้าอ้าง BOQ → ดึง **6-1, 6-3, 6-4** มาแสดง (ราคาขาย) · **ไม่แสดง 6-2** (ของแถม ไม่คิดเงิน)
- ผูกลูกค้า · เลือกไซต์ · ส่วนลด · **VAT 7% เปิด/ปิดตามลูกค้า** · ยอดสุทธิ
- สถานะ: ร่าง → ส่งแล้ว → **อนุมัติ** / ปฏิเสธ / หมดอายุ · พิมพ์ (หัวบริษัท+โลโก้) · คัดลอกส่งลูกค้า

## 5) กำไร (เฉพาะใบที่อนุมัติ)
**กำไร = ยอดขายสุทธิ(ใบเสนอราคา ก่อน VAT − ส่วนลด) − ต้นทุนสุทธิ(BOQ ทุกส่วน)**

## 6) บทบาทผู้ใช้ (เพิ่ม "ฝ่ายขาย")
- exec (ผู้บริหาร) · admin (ธุรการ/จัดซื้อ) · **sales (ฝ่ายขาย × 3)** · tech (ช่าง)
- ฝ่ายขาย: สร้างลูกค้า/BOQ/ใบเสนอราคา + **จัดคิวงาน + มอบหมายช่าง**

## 7) ใบงาน (Job Order) + จัดคิว + มอบหมายช่าง
- ใบเสนอราคา "อนุมัติ" → สร้าง **ใบงาน** อัตโนมัติ: ข้อมูลลูกค้า · ผู้ติดต่อ+เบอร์ · ไซต์+**ลิงก์แผนที่** · รายการที่ต้องทำ (จากใบเสนอราคา/BOQ) · หมายเหตุ
- **มอบหมายทีมช่าง** (เลือกจากชื่อทีม) + **เลือกวัน/เวลา** → เข้าคิวงานของทีม
- สถานะงาน: รอจ่ายงาน → นัดแล้ว → กำลังทำ → เสร็จ

## 8) ฝั่งช่าง (Technician Web App) — ดีไซน์
มุมมองมือถือ (มีอยู่แล้ว ต่อยอด):
- **งานของฉัน/ทีม:** รายการใบงานที่ถูกมอบหมาย เรียงตามวัน/เวลา · แตะดูรายละเอียด
- **รายละเอียดงาน:** ลูกค้า · เบอร์โทร (กดโทรได้) · ที่อยู่ + **เปิดแผนที่** · รายการแอร์/วัสดุที่ต้องติดตั้ง · หมายเหตุ
- **ในงาน:** เบิกวัสดุสำหรับงานนี้ (ผูก job อัตโนมัติ) · คืนของเหลือ · อัปเดตสถานะ (รับงาน → กำลังทำ → เสร็จ) · แนบรูปหน้างาน
- สถานะ/การเบิกไหลกลับไปที่ฝ่ายขาย/ธุรการ + เข้าสู่ต้นทุนจริงของงาน

## โครงตารางข้อมูล (สรุป)
- `items` (เดิม materials ขยาย): type(ac/service/material), brand, btu, sub-category, cost, sale_price, ...
- `customers`, `customer_contacts`, `customer_sites`
- `boqs`, `boq_items` (section 6-1..6-4)
- `quotations`, `quotation_items` (อ้าง boq ได้)
- `jobs` (ขยาย): customer_id, site_id, quote_no, assigned_team, scheduled_at, status, map_url, details
- (ใช้ movements/job cost เดิมต่อได้เลย)

## แผนเป็นเฟส (ส่งมอบทีละชิ้น)
1. **CRM ลูกค้า** (ประเภท/VAT/ผู้ติดต่อหลายคน/ไซต์หลายที่)
2. **คลัง v2** (ชนิด AC/บริการ/วัสดุ + ยี่ห้อ/BTU + ตัวกรอง)
3. **BOQ** (4 ส่วน · ต้นทุน)
4. **ใบเสนอราคา** (ดึงจาก BOQ · ส่วนลด · VAT ตามลูกค้า · อนุมัติ · พิมพ์)
5. **กำไร** (อนุมัติแล้ว: ยอดขาย − ต้นทุน BOQ)
6. **ใบงาน + จัดคิว + มอบช่าง**
7. **ฝั่งช่าง** (งานของฉัน · แผนที่ · เบิก-คืนในงาน · อัปเดตสถานะ)
