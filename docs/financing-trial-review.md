# ค่างวด — ชุดป้องกันแรก (ร่างทดลอง)

ยังไม่พร้อม merge หรือใช้แทนระบบจ่ายเงินครบวงจร

## ปัญหาที่แก้

- ฐานข้อมูลที่อ่านเมื่อ 10 ก.ย. 2569 ไม่มี loans.submitted_seq แม้ migration 242 ใน repo มีคอลัมน์นี้แล้ว
- เดิมตั้งเบิกสำเร็จแล้วอัปเดต submitted_seq ไม่ได้ จะเพิ่ม paid_count แทน ทำให้ตั้งเบิกถูกนับเหมือนจ่าย
- เดิมยืนยันจ่ายโดยไม่มี submitted_seq ยังเพิ่ม paid_count ได้
- เดิมเส้นหักอัตโนมัติไม่ตรวจว่าตั้งเบิกงวดเดียวกันไว้แล้ว

## พฤติกรรมทดลอง

ตรวจสถานะก่อนสร้างใบเบิก ขาด/ไม่ถูกต้องให้หยุด ไม่มีการเขียนจากคำขอนั้น เลิก fallback เพิ่ม paid_count กรณีตั้งเบิก กันหักอัตโนมัติเมื่อมีงวดตั้งเบิก และยืนยันได้เฉพาะงวดถัดไปที่ตั้งเบิกไว้

## ข้อจำกัดที่ต้องทำต่อก่อนใช้งานจริง

- ยังไม่ผูก expense_id กับสัญญา/เลขงวด จึงยังไม่พิสูจน์ว่าจ่ายครบจากเอกสารจริงก่อนยืนยัน
- การสร้างใบเบิกและอัปเดตสัญญายังเป็นสองคำขอ หากคำขอหลังล้ม อาจมีใบเบิกค้าง ต้องตรวจรายการเดิมก่อนกดใหม่
- ยังไม่กันแข่งขันข้ามเครื่อง และไม่แก้ payRecurringBill/generateRecurringExpenses
- งานถัดไปต้องใช้การทำรายการแบบ atomic พร้อมรหัสอ้างอิงเฉพาะงวด และพิจารณาการจ่ายบางส่วน/ปฏิเสธ/ยกเลิก/รวมใบเบิก
- ไม่แก้ paid_count เก่าย้อนหลัง ไม่เดาผลจากโน้ต ไม่รัน migration จริง
- อย่าเปิด preview ที่ต่อฐานข้อมูลจริงเพื่อทดลองกด เพราะหน้ากระแสเงินสดมี on-open sync
